# Changelog

All notable changes to this project are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and
this project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
Consumers pin the reusable workflows to a released tag; see
[RELEASING.md](RELEASING.md). From v1.0.1 the version sections below are
generated by commitizen from the Conventional-Commit history.

## v1.0.0 (2026-07-14)

Initial public release: an AI quiz merge gate for GitHub pull requests, backed
by Databricks. A pull request may merge only when the latest published quiz
result for its head commit scored 100%.

### Added

- **Databricks bundle-init template** (`databricks_template_schema.json` +
  `template/{{.project_name}}/`) deploying the backend: a Unity Catalog schema,
  a serverless quiz-generation job, and a Streamlit quiz app.
- **Quiz generation** from the PR diff: the question count scales with diff
  size and a model-judged difficulty factor; questions are over-generated for
  retake variety and written to a `question_pool` Delta table.
- **Streamlit quiz app** that samples questions per attempt, grades them,
  records results, posts the `quiz-gate` commit status on every attempt, and
  publishes a pass comment with AI explanations to the PR.
- **Reusable GitHub workflows** (`on: workflow_call`): `quiz-generate.yml`
  (auto-generate on PR open/reopen, regenerate on `/quiz`, mark the gate pending
  on new commits) and `quiz-gate.yml` (re-evaluate on `/quiz-check` or manual
  dispatch), plus the `gate-check` composite action.
- **Bot quiz-waiver** (`QUIZ_WAIVE_AUTHORS`, default `dependabot[bot]`):
  allow-listed automated-dependency PRs receive an automatic passing status and
  skip the quiz.
- **Caller templates** (`templates/callers/`) consumers copy into their repos,
  and dogfood callers (`.github/workflows/caller-*.yml`) for this repo.
- **Guided installer** (`installer/pr_quiz_install.py`, standard-library only):
  `doctor` preflight, `backend` (deploy + service principal + grants), and
  `onboard` (wire a consumer repo).
- **Release automation** with commitizen: Conventional-Commit PR-title linting
  and two-stage `release-prep` / `release-publish` workflows that tag, move the
  `v1` alias, and publish a GitHub Release.
- **Security and supply-chain hardening**: comment triggers gated on author
  association, event-derived values passed through env vars (no inline
  expression in shell), SHA-pinned third-party actions, a checksum-verified
  actionlint download, a pinned dev-dependency manifest, Dependabot updates, and
  a same-repo guard so fork PRs never receive secrets.
- **Project CI** (`.github/workflows/ci.yml`): pytest, actionlint, zizmor, and
  repo-hygiene grep gates, plus a tag-only release gate.
- **Documentation**: adopter guide, operator guide, and threat model under
  `docs/`, plus `SECURITY.md`, `CONTRIBUTING.md`, and `RELEASING.md`.
